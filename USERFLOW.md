
# 📋 User Flow - Rocky RDF Bot v3.2

> **Статус проекта:** ✅ Production Ready (Фаза 1 завершена)  
> **Последнее обновление:** 13 ноября 2025 г.  
> **Архитектура:** Vercel Functions + Airtable + n8n + Telegram Bot

Детальное описание пользовательских сценариев и взаимодействий в системе Rocky RDF Bot.

## 🎯 Обзор системы

Rocky RDF Bot — это Telegram Web App для управления съемочной командой с интеграцией:
- **Frontend:** HTML/CSS/JS веб-приложения на Vercel
- **Backend:** Vercel Functions (API)
- **База данных:** Airtable (таблица "Пользователи")
- **Автоматизация:** n8n workflow
- **Интерфейс:** Telegram Bot (@Rocky_RDF_Admin)

## 🔄 User Flow Overview

### Типы пользователей:
- **👤 Новый пользователь** - впервые взаимодействует с ботом

- **✅ Одобренный пользователь** - имеет полный доступ к системе
- **🔐 Администратор** - управляет пользователями и системой

## 📱 СЦЕНАРИЙ 1: Регистрация нового пользователя ✅

> **Статус:** РЕАЛИЗОВАНО И РАБОТАЕТ

### 1.1 Первичное взаимодействие

**Действие пользователя:**
1. Пользователь находит бота `@Rocky_RDF_Admin` в Telegram
2. Нажимает "Start" или отправляет `/start`

**Системная реакция:**
1. [`n8n workflow`](N88n_part/[MAIN]%20Rocky_v2_webapp-10.json:1) получает событие
2. [`Extract User Data`](N88n_part/[MAIN]%20Rocky_v2_webapp-10.json:292) извлекает данные пользователя:
   - `chat_id`
   - `username`
   - `first_name`
   - `last_name`
   - `full_name`

### 1.2 Проверка существующей регистрации

**Системные действия:**
1. [`Check Existing Registration`](N88n_part/[MAIN]%20Rocky_v2_webapp-10.json:304) проверяет в Airtable
2. Поиск по формуле: `{chat_id} = "{{ $json.chat_id }}"`
3. Проверяется статус: `Pending`, `Approved`, `Blocked`

**Возможные сценарии:**
- **Новый пользователь** → переход к созданию заявки
- **Существующий (Approved)** → уведомление "Вы уже зарегистрированы!"
- **Существующий (Pending)** → уведомление "Заявка ожидает одобрения"
- **Существующий (Blocked)** → уведомление "Доступ заблокирован"

### 1.3 Создание заявки на регистрацию

**Системные действия (если пользователь новый):**
1. [`Create a record`](N88n_part/[MAIN]%20Rocky_v2_webapp-10.json:346) создает запись в Airtable:
   ```json
   {
     "@username": "@username",
     "chat_id": 182719187,
     "FirstName": "Имя",
     "LastName": "Фамилия", 
     "Role": "USER",
     "Статус доступа": "Pending"
   }
   ```

### 1.4 Уведомление администратора

**Системные действия:**
1. [`to Admin`](N88n_part/[MAIN]%20Rocky_v2_webapp-10.json:636) отправляет сообщение администратору (ID: 182719187)
2. Сообщение содержит:
   - ФИО пользователя
   - Chat ID
   - Username
   - Inline кнопки: "✅ Одобрить" / "❌ Отклонить"

**Формат callback кнопок:**
- Одобрить: `approve_{chat_id}_{record_id}`
- Отклонить: `block_{chat_id}_{record_id}`

## 🛡️ СЦЕНАРИЙ 2: Модерация заявок (Администратор) ✅

> **Статус:** РЕАЛИЗОВАНО И РАБОТАЕТ

### 2.1 Получение уведомления

**Администратор получает:**
```
🔔 *Новая заявка на регистрацию*

👤 *Пользователь:* Егор Никитин
🆔 *ID:* `182719187`
📝 *Username:* @urso_barbudos

[✅ Одобрить] [❌ Отклонить]
```

### 2.2 Принятие решения

**Действие администратора:**
- Нажимает "✅ Одобрить" или "❌ Отклонить"

**Системная реакция:**
1. [`Parse callback DATA`](N88n_part/[MAIN]%20Rocky_v2_webapp-10.json:254) обрабатывает нажатие:
   ```javascript
   // Разбор callback_data: "approve_182719187_recABCDE"
   const parts = callbackData.split('_');
   const action = parts[0]; // "approve" или "block"
   const target_chat_id = parts[1];
   const record_id = parts[2];
   ```

2. [`Update Status`](N88n_part/[MAIN]%20Rocky_v2_webapp-10.json:766) обновляет статус в Airtable:
   - Одобрение: `Статус доступа` = `"Approved"`
   - Отклонение: `Статус доступа` = `"Blocked"`

### 2.3 Уведомление пользователя

**При одобрении:**
- [`Notify User`](N88n_part/[MAIN]%20Rocky_v2_webapp-10.json:267): "✅ Поздравляю! Ваша заявка одобрена!"
- [`to Admin1`](N88n_part/[MAIN]%20Rocky_v2_webapp-10.json:718): Подтверждение администратору

**При отклонении:**
- [`Notify User1`](N88n_part/[MAIN]%20Rocky_v2_webapp-10.json:741): "❌ Заявка отклонена"

### 3.1 Доступ к профилю

**Действие пользователя:**
1. В Telegram боте нажимает Menu Button "Мой профиль"
2. Открывается Web App: [`public/profile/profile.html`](public/profile/profile.html:1)

### 3.2 Инициализация Web App

**Системные действия:**
1. [`initializeTelegram()`](public/profile/profile.html:62) проверяет доступность Telegram WebApp SDK
2. [`diagnoseTelegramWebApp()`](public/profile/profile.html:21) выполняет диагностику:
   - Проверка `window.Telegram.WebApp`
   - Извлечение `tg.initData` и `tg.initDataUnsafe.user`
   - Логирование всех параметров для отладки

### 3.3 Проверка аутентификации

**Безопасность (Production):**
```javascript
if (tg && tg.initDataUnsafe && tg.initDataUnsafe.user) {
    // ✅ Реальные данные из Telegram
    user = tg.initDataUnsafe.user;
    userId = user.id;
} else {
    // ❌ БЛОКИРОВКА: "Доступ только через Telegram"
    // Показ инструкции по открытию через бота
}
```

**Режим разработки (Localhost):**
```javascript
if (isDevelopment) {
    // ✅ Fallback к тестовому пользователю
    userId = 182719187;
}
```

### 3.4 Загрузка данных профиля

**API запрос:**
```javascript
// GET https://rdf-rocky-bot-twa.vercel.app/api/profile?chat_id=182719187
const userProfileData = await loadUserProfile(userId);
```

**Обработка в [`api/profile.js`](api/profile.js:154):**
1. [`checkUserAccess()`](api/profile.js:81) проверяет статус пользователя в Airtable
2. Возможные ответы:
   - **403 Forbidden:** Пользователь не одобрен
   - **200 OK:** Данные профиля для одобренных пользователей

**Структура ответа:**
```json
{
  "success": true,
  "data": {
    "chat_id": 182719187,
    "username": "@urso_barbudos",
    "first_name": "Егор",
    "last_name": "Никитин", 
    "phone": "",
    "payment_details": "СБП +79991234567",
    "notes": "Оператор камеры",
    "status": "Approved",
    "role": "USER"
  }
}
```

### 3.5 Отображение интерфейса

**Заголовок:**
- Отображение: "Егор Никитин @urso_barbudos"

**Только для чтения:**
- Username: `@urso_barbudos`
- Телефон: `Не указан` (пока не реализовано)

**Редактируемые поля:**
- Платежные реквизиты (textarea)
- Заметки (textarea)

### 3.6 Сохранение изменений

**Действие пользователя:**
- Нажимает Telegram MainButton "💾 Сохранить изменения"

**API запрос:**
```javascript
// POST https://rdf-rocky-bot-twa.vercel.app/api/profile
await saveUserProfile(userId, {
    payment_details: "новые реквизиты",
    notes: "обновленные заметки"

```

**Обработка в [`api/profile.js`](api/profile.js:206):**
1. Проверка доступа пользователя
2. Обновление полей в Airtable через [`airtable.update()`](api/profile.js:240)
3. Ответ: `{"success": true, "message": "Профиль успешно обновлен"}`

**Пользовательская обратная связь:**
- [`tg.showAlert()`](public/profile/profile.html:421): "✅ Профиль успешно сохранен!"

## 🔧 СЦЕНАРИЙ 6: Админ-панель управления 🚧

> **Статус:** ЗАПЛАНИРОВАНО (Фаза 3)

### 6.1 Доступ к админ-панели

**Планируемая проверка прав:**
1. Пользователь отправляет `/admin` в Telegram
2. n8n проверяет поле `Role` в Airtable
3. Если `Role = "ADMIN"` → отправка кнопки с админ-панелью
4. Если `Role ≠ "ADMIN"` → "Доступ запрещен"

### 6.2 Управление расходами

**Планируемая функциональность:**

**Интерфейс админа:**
- Список неутвержденных расходов
- Для каждого расхода:
  - Данные пользователя
  - Название, сумма, описание
  - Прикрепленный чек (если есть)
  - Кнопки: "Утвердить" / "Отклонить"
  - Поле для комментария

**API endpoints:**
- `GET /api/expenses?status=pending` - список ожидающих расходов
- `POST /api/expenses/approve` - утверждение расхода
- `POST /api/expenses/reject` - отклонение расхода

### 6.3 Уведомления пользователей

**Планируемый процесс:**
1. Администратор принимает решение по расходу
2. Система автоматически уведомляет пользователя в Telegram
3. Сообщения: "✅ Расход утвержден" / "❌ Расход отклонен (причина)"

## 🔐 Security & Access Control

### Уровни доступа

#### Новый пользователь
- ✅ Может подать заявку на регистрацию через `/start`
- ❌ Нет доступа к Web Apps
- ❌ Нет доступа к API

#### Ожидающий (Pending)
- ✅ Заявка подана
- ❌ Нет доступа к Web Apps до одобрения
- ❌ Все API запросы возвращают 403 Forbidden

#### Одобренный пользователь (Approved) 
- ✅ Полный доступ к профилю
- ✅ Просмотр вызывных листов (планируется)
- ✅ Отправка обратной связи (планируется)
- ✅ Добавление расходов (планируется)

#### Администратор (Admin Role)
- ✅ Все права обычного пользователя
- ✅ Модерация заявок на регистрацию
- ✅ Управление статусами пользователей
- ✅ Админ-панель управления расходами (планируется)
- ✅ Создание вызывных листов (планируется)

#### Production Security

```javascript
// Проверка в public/profile/profile.html
```

## 🚨 Известные ограничения и решения

### Текущие ограничения:

#### 1. Отсутствие валидации Telegram initData 🚧
**Проблема:** API endpoints не проверяют подлинность Telegram данных
**Решение (планируется):** Добавить HMAC-SHA256 валидацию в Vercel Functions

#### 2. Отсутствие офлайн режима 🚧  
**Проблема:** Web Apps не работают без интернета
**Решение (планируется):** Service Worker для кэширования критических данных

#### 3. Отсутствие graceful degradation при сбоях API 🚧
**Проблема:** Нет плавной деградации при отсутствии API
**Решение (планируется):** Fallback интерфейсы с базовой функциональностью

#### 4. Отсутствие detailed logging 🚧
**Проблема:** Сложно отлаживать проблемы пользователей  
**Решение (планируется):** Комплексное отслеживание ошибок и пользовательская аналитика

### Решенные проблемы:

#### 1. ✅ Утечка данных администратора (v3.2)
**Было:** Fallback к данным админа при отсутствии tg.initData
**Стало:** Строгая блокировка доступа на production

#### 2. ✅ HTTP 308 редиректы (v3.2)
**Было:** Неправильные заголовки вызывали редиректы
**Стало:** Правильная конфигурация CORS и заголовков

#### 3. ✅ Cloudflare недоступность из РФ
**Было:** Cloudflare заблокирован для российских пользователей
**Стало:** Полная миграция на Vercel

## 🗺️ User Journey Map

### New User Journey (Новый пользователь)
```
👤 Discovery → 📱 Start Bot → 📝 Registration → ⏳ Pending → ✅ Approval → 🎯 Onboarding
    |           |              |               |           |            |
1-2 min     30 sec         2 min         1-24 hours    instant     5 min
```

**Детали каждого этапа:**
1. **Discovery**: Пользователь узнает о боте от коллег/руководства
2. **Start Bot**: Находит `@Rocky_RDF_Admin`, нажимает Start
3. **Registration**: n8n собирает данные, создает заявку в Airtable
4. **Pending**: Ожидание решения администратора 
5. **Approval**: Администратор одобряет через inline кнопки
6. **Onboarding**: Пользователь настраивает профиль в Web App

### Regular User Journey (Обычный пользователь)
```
📱 Notification → 📋 View Callsheet → 🎬 Attend Shoot → 💬 Feedback → 💰 Submit Expenses
     |              |                  |               |              |
   instant        1 min             8 hours          2 min         3 min
```

### Admin Journey (Администратор)
```
📝 Create Callsheet → 👥 Assign Team → 📨 Send Notifications → 📊 Review Feedback → 💸 Approve Expenses
      |                   |               |                  |                |
```
