**3. Настройка n8n на Amvera (`https://n8n---bots-ursobarbudos.amvera.io/`):**

*   **Держи под рукой две вкладки:** одну с воркфлоу, другую с `Executions`, чтобы сразу видеть результаты выполнения и отлавливать ошибки.

**4. Настройка Airtable:**
*   Открой свою базу. Держи под рукой `Base ID` и названия таблиц.

### Фаза 1: Профиль пользователя (Фундамент) - В РАБОТЕ

**Цель: Создать основу для персонализации. Пользователь сможет просматривать и редактировать свой профиль.**

#### Шаг 1.1: Airtable — Подготовка таблицы "Пользователи"
Убедись, что твоя таблица `Пользователи` содержит поля: `chat_id` (Number), `@username` (Text), `Контактный телефон` (Phone), `Роль` (Single Select), `Платежные реквизиты` (Multiline Text), `Примечание` (Multiline Text).

#### Шаг 1.2: n8n — Создание API для профиля
Нам нужно два воркфлоу для взаимодействия с профилем.

**Воркфлоу №1: `[TWA] Profile - GET`** (Отдает данные профиля)
1.  **Триггер:** `Webhook`.
    *   Метод: `GET`.
    *   Путь: `profile/get`.
    *   Скопируй **Test URL** для локальной отладки.
2.  **Узел:** `Airtable (Search)`.
    *   Операция: `Search`.
    *   База и таблица: твоя база и таблица "Пользователи".
    *   **Filter by formula:** `({chat_id} = "{{ $request.query.chat_id }}")` — это магия, которая ищет запись по `chat_id`, пришедшему в URL.
3.  **Узел:** `Respond to Webhook`.
    *   Он отправит данные обратно в Web App. В поле `Response Body` вставь: `{{ $('Airtable (Search)').item.json.fields }}`.
4.  **Активируй воркфлоу.** Скопируй **Production URL**.

**Воркфлоу №2: `[TWA] Profile - SAVE`** (Сохраняет данные профиля)
1.  **Триггер:** `Webhook`.
    *   Метод: `POST`.
    *   Путь: `profile/save`.
2.  **Узел:** `Airtable (Upsert)`.
    *   Операция: `Upsert`.
    *   База и таблица: "Пользователи".
    *   **Columns to Match By:** `chat_id`.
    *   **Columns:** Сопоставь поля из Airtable c данными из Web App. Например:
        *   `chat_id`: `{{ $json.body.chat_id }}`
        *   `Контактный телефон`: `{{ $json.body.phone }}`
        *   `Платежные реквизиты`: `{{ $json.body.paymentDetails }}`
        *   ... и так далее.
3.  **Активируй воркфлоу.** Скопируй **Production URL**.

#### Шаг 1.3: VS Code — Создание `profile.html`
1.  Создай в VS Code файл `profile.html`.
2.  Вставь туда HTML-разметку с полями формы (`input` для телефона, `textarea` для реквизитов и т.д.).
3.  **Ключевая логика на JavaScript:**
    ```javascript
    const tg = window.Telegram.WebApp;
    const userId = tg.initDataUnsafe.user.id;
    
    // ЗАМЕНИ НА СВОИ URL ИЗ n8n
    const GET_URL = "https://n8n---bots-ursobarbudos.amvera.io/webhook/profile/get";
    const SAVE_URL = "https://n8n---bots-ursobarbudos.amvera.io/webhook/profile/save";

    // 1. При загрузке страницы, получаем данные профиля
    document.addEventListener('DOMContentLoaded', function() {
        fetch(`${GET_URL}?chat_id=${userId}`)
            .then(response => response.json())
            .then(data => {
                // Заполняем поля формы данными из Airtable
                document.getElementById('phone').value = data['Контактный телефон'] || '';
                document.getElementById('payment').value = data['Платежные реквизиты'] || '';
                // ... и т.д. для всех полей
            });
    });

    // 2. При нажатии на главную кнопку, сохраняем данные
    tg.MainButton.setText('Сохранить изменения');
    tg.MainButton.show();
    tg.onEvent('mainButtonClicked', function() {
        const dataToSave = {
            chat_id: userId,
            phone: document.getElementById('phone').value,
            paymentDetails: document.getElementById('payment').value,
            // ... и т.д. для всех полей
        };

        fetch(SAVE_URL, {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify(dataToSave)
        }).then(() => {
            tg.close(); // Закрываем Web App после сохранения
        });
    });
    ```

#### Шаг 1.4: Развертывание и интеграция
1.  Загрузи готовый `profile.html` в твой репозиторий на GitHub.
2.  В `@BotFather` создай команду `/profile`, указав для нее ссылку `https://your-username.github.io/rdf-bot-twa/profile/profile.html`.
3.  **Тестируй!** Отправь боту `/profile`, убедись, что форма открывается, данные подгружаются. Измени что-нибудь, сохрани и проверь, обновилась ли запись в Airtable.

### Фаза 2: Пользовательские фичи

#### Cценарий 2: Интерактивный вызывной лист (`callsheet.html`)

1.  **n8n Workflow `[TWA] Callsheet - GET`**:
    *   **Триггер:** `Webhook (GET)` с путем `callsheet/get`.
    *   **Узел:** `Airtable (Get)`. Ищет запись по `record_id`, который мы передадим в URL: `{{ $request.query.id }}`.
    *   **Узел:** `Respond to Webhook` (отправляет данные).
2.  **Основной воркфлоу бота (модификация):**
    *   Когда ты рассылаешь вызывные, кнопка "Посмотреть вызывной" теперь должна вести на URL вида: `https://your-username.github.io/rdf-bot-twa/callsheet/callsheet.html?id={{ $json.recordId }}`. Переменная `{{ $json.recordId }}` будет содержать ID записи из Airtable.
3.  **VS Code `callsheet.html`:**
    *   **JS:** С помощью `new URLSearchParams(window.location.search).get('id')` получает ID вызывного из URL.
    *   Делает `fetch`-запрос к n8n-воркфлоу, чтобы получить данные.
    *   "Рисует" страницу, красиво раскладывая информацию по блокам. Для карты формирует ссылку на Яндекс.Карты.

#### Cценарий 3: Форма обратной связи (`feedback.html`)

1.  **Airtable:** Создай таблицу "Фидбэк".
2.  **n8n Workflow `[TWA] Feedback - SAVE`**:
    *   Простейший воркфлоу `Webhook (POST)` -> `Airtable (Create)`, который создает новую запись в таблице "Фидбэк".
3.  **n8n Workflow `[SCHED] Запрос фидбэка`**:
    *   **Триггер:** `Schedule`, настроенный на ежедневный запуск.
    *   Далее цепочка узлов, которая находит вчерашние смены, их участников и рассылает им сообщения с кнопкой, ведущей на `feedback.html?shift_id=...`.
4.  **VS Code `feedback.html`**:
    *   Простая форма со звездочками (рейтинг) и текстовыми полями.
    *   JS при отправке собирает данные и `shift_id` из URL, отправляя всё в n8n.

### Фаза 3: Админ-инструменты

#### Cценарий 4: Админ-панель утверждения расходов (`admin_expenses.html`)

1.  **Airtable:** В таблице расходов добавь поле `Статус` (`Single Select`: `На проверке`, `Утверждено`, `Отклонено`).
2.  **Основной воркфлоу бота (модификация):**
    *   При получении команды `/admin` (или любой другой), первым делом делай `Airtable (Search)` по `chat_id` отправителя.
    *   Узел `If` проверяет, `{{ $json.fields.Role === 'Admin' }}`.
    *   Если да — отправляй админу сообщение с кнопкой, ведущей на `admin_expenses.html`. Если нет — игнорируй или пиши "Доступ запрещен".
3.  **n8n Workflows для админ-панели:**
    *   `[TWA] Admin - GET Expenses`: `Webhook (GET)` -> `Airtable (Search)` со статусом "На проверке" -> `Respond to Webhook`.
    *   `[TWA] Admin - UPDATE Expense`: `Webhook (POST)` -> `Airtable (Update)` (обновляет статус записи по `record_id`) -> `Telegram (Send message)` (отправляет уведомление пользователю).
4.  **VS Code `admin_expenses.html`:**
    *   **JS:** При загрузке запрашивает список трат. В цикле создает для каждой траты HTML-блок с данными и кнопками.
    *   На кнопки "утвердить/отклонить" вешается обработчик, который отправляет в n8n запрос на обновление статуса, передавая `record_id` и новый статус. После успеха — скрывает обработанный блок со страницы.
